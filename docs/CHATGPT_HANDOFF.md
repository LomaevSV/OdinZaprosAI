## 2. Архитектура
```text
UI/JSON API → Оркестратор (детерминированный автомат хода, единственный вызывающий инструменты)
  ├─ LLM Gateway: Интерпретатор (текст → InterpretationDelta) и Composer (переформулировка); без инструментов
  ├─ Ядро (код): календарь, деньги, условия, ранжирование RANK-01, стыки, полнота, пересборка, корзина
  └─ Tool Registry (только чтение, deny-by-default, лимиты, circuit breaker)
        └─ Режимы: Live → строгий Replay → (только mixed) ДЕМО по компоненту → честный unknown
              ├─ MCP-клиент → Tutu (rail, avia, hotels)
              ├─ REST → Open-Meteo geocoding, OSRM table
              └─ Mock-генератор «ДЕМО», редакционный каталог
```
Отдельных LLM-агентов по доменам нет (план §2.6): домены — код. «Агенты» = 2 роли LLM.

**Интерпретация свободного запроса:**
1. Текст очищается от секретов и длинных номеров (`[скрыто]`).
2. Модели передаются текущее сообщение и краткие условия поездки, без истории.
3. LLM возвращает значения с **дословными цитатами**; цитату, которой нет в тексте, код отклоняет.
4. Даты LLM не вычисляет: календарь разбирает фразы («с 3 по 7 декабря», «на 3 ночи»; «на 3 дня» → вопрос).
5. Изменения накладываются на прежние условия, неразобранное сохраняется как `unparsed`.
6. `TripRequest` строится тем же кодом, что и для формы.

| Решает LLM | Решает код |
|---|---|
| какие параметры есть в тексте (с цитатой), обязательность по формулировке | даты, часовые пояса, суммы (`Decimal`), валюты, выполнение условий, ранжирование, полнота цены, наличие, стыки, корзина, причины остановки |
| связный текст ответа | проверка чисел ответа по таблице фактов; при нарушении — шаблон |

- **Уточнения:** политика UC-02. Не предполагаются: откуда, куда, даты, бюджет, состав (DEC-25). Задаётся один раунд блокирующих вопросов, ответ дополняет прежнее.
- **Ранжирование:** классы RANK-01 (все обязательные выполнены → неизвестны → нарушены); внутри класса — число подтверждённых совпадений, затем канонический ID. Цена класс не поднимает (DEC-26).
- **Пересборка:** таблица REPLAN-01, инвалидируются только зависимые роли; явные выборы переносятся, если не устарели (TTL 30 мин, DEC-21); неудачная пересборка не записывается.
- **Корзина:** `draft → awaiting_confirmation → demo_purchased`, два раздельных согласия (покупка и риски), идемпотентный демо-чек.

**Не реализовано:**
- детали отеля (`get_offer_details`) для подтверждения наличия;
- несколько номеров в Tutu;
- автобусы и мультимодальные маршруты (P1);
- климатические нормы и OurAirports (DEC-12), 2ГИС (DEC-13);
- отзывы (P1);
- `sufficient_results` выключен (DEC-22).

## 4. Готовность к демонстрации
- **Локально:** `uv sync` → `uv run python -m odin.api` → `http://localhost:8080` (`.env` читается автоматически).
- **Docker:** `docker compose up --build` → `http://localhost:8080`; healthcheck — `python -m odin.healthcheck`. Нужен Docker Compose ≥ 2.24.
- **Переменные `.env` (без значений):**
  - режим данных: `ODIN_DATA_MODE` (по умолчанию `auto`);
  - LLM: `ODIN_LLM_MODE`, `ODIN_LLM_BASE_URL`, `ODIN_LLM_MODEL`, `ODIN_LLM_API_KEY` (запасные имена — `OPENAI_*`);
  - необязательные: `ODIN_LLM_COMPOSER`, `ODIN_LLM_JSON_MODE`, `ODIN_LLM_TEMPERATURE`. Полный список — `.env.example`.
- **Можно показать честно:**
  - форма Москва → Казань в `live` (данные Tutu + оценка трансфера OSRM) или в `mock`;
  - уточняющие вопросы;
  - пересборка с сохранением условий, корзина с двумя согласиями и идемпотентный демо-чек;
  - маркировка режима каждого компонента;
  - отказ без LLM (честный);
  - Replay без сети.
- **Нельзя выдавать за работающее:**
  - свободный диалог на реальной модели (не прогонялся);
  - подтверждённое наличие мест и номеров;
  - полную стоимость (всегда `partial`);
  - стоимость трансфера;
  - общественный транспорт;
  - климат и визы;
  - запуск в Docker (не проверен);
  - покрытие городов за пределами проверенных пар (Live проверен только на Москве и Казани).
