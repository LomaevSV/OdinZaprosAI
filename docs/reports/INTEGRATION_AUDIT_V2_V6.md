## 4. Решения, отличающиеся от пакетов аудита

### 4.1. INT-002 — закрытый словарь городов отклонён
Патч аудита принимал падежные формы только для 8 городов; для остальных требовал дословное совпадение
именительного падежа. На ветке это сломало **9 из 22** падежных формулировок защитного набора:
«из Ростова-на-Дону», «в Ростове-на-Дону», «из Перми», «из Твери», «из Орла», «в Йошкар-Олу»,
«из Набережных Челнов», «в Великом Новгороде», «в Самару». Это основной сценарий (город назван в любом падеже).
Принято: основа слова + окончание до 3 букв, прилагательные («Нижний» → «Нижнего», «Набережные» →
«Набережных»), беглая гласная («Орёл» → «Орла»), составные названия через дефис/пробел, словарь сокращений.
Подмена «Из Москвы» → «Сочи» и 5 других подмен отклоняются.

### 4.2. INT-003 — коррекция обязательности вместо отклонения значения
Патч отклонял **всё значение** при расхождении `required` с признаком цитаты: «Не дороже 40000», ответ
модели `required=false` → бюджет терялся целиком. Принято: значение применяется, обязательность определяет
код по явному признаку (правило 6 промпта), пользователь получает пометку. Тест аудита допускает оба
варианта. Исправлена ошибка регулярного выражения аудита: «не обязательно» совпадало с «обязательно» и
делало условие обязательным. При одновременных признаках («желательно не дороже…») сохраняется решение модели.

### 4.3. INT-004 — диапазон бюджета
Аудит отклонял любой диапазон («от 40 до 50 тысяч»), из-за чего бюджет не применялся. Бюджет в контракте —
верхняя граница (`budget_total lte`), поэтому принят **верхний конец** диапазона; нижний конец и одна нижняя
граница («от 40 тысяч») лимитом не считаются и отклоняются. Ожидание `test_audit_v2_interpreter.py`
для `('Бюджет от 40 до 50 тысяч рублей', '50000')` изменено с `False` на `True` с комментарием.
Дополнительно поддержаны «1,5 млн» (патч ломал защитный случай), «50к», «120 тыс.руб.».

### 4.4. INT-005 — признаки отмены
Патч разрешал 1–2 точные фразы на поле. Не проходили обычные отмены: «любой бюджет», «цена не важна»,
«неважно, сколько стоит», «самолёт тоже подойдёт», «любой транспорт», «можно без завтрака», «собака не едет»,
«дети остаются дома», «только взрослые». Принято: тема поля и признак отмены в одной части фразы; части
делятся по `, . ; : ! ?` и союзам «но/а/однако/зато/хотя»; часть с признаком обязательности отменой не
считается. Отклоняются: «Бюджет до 40000» (исходный пример аудита), «Бюджет до 40000, транспорт не важен»
(для бюджета), «С собакой, транспорт не важен» (для животных), «Поезд без пересадок», «Только поездом и звёзды
не важны» и др. При отклонении условие сохраняется, пользователь получает пометку.

### 4.5. TREE-001 — оценка семантики OR
Исправление принято, потому что:
1. Контракт модуля (`core/tree.py:4`, корпус K-10, S3_REPORT) прямо требует: «циклы … — `unknown` с причиной,
   а не исключение и не `matched`».
2. До исправления результат **зависел от порядка групп** [проверено на коде снимка]: для `a = OR(b, known)`,
   `b = AND(a, known)` порядок `[a, b]` давал `a=matched, b=unknown`, порядок `[b, a]` — оба `matched`
   (цикл «подтверждён»).
3. Семантика OR **вне цикла сохранена**: `root = OR(known, a)` при `known=matched` → `matched`
   (`test_or_outside_cycle_keeps_matched_branch`); ацикличный OR не изменился.
4. `evaluate_tree` в рабочем пути оркестратора не вызывается — исправление не влияет на основной сценарий.

### 4.6. Стилевые правки тестов аудита
`ruff --fix` (порядок импортов) во всех 6 файлах; в `test_audit_v3.py` — разнесение `if …: assert` по строкам
и `pytest.raises(Exception)` → `ValidationError` (B017). Ужесточение до `ValidationError` и выявило INT-006.
