## Принятые трактовки (в рамках ТЗ, на проверку руководителю)
1. Даты — `blocking_now`, если направление известно (без дат поиск с ценой невозможен); для вдохновения — `optional`.
2. Неудачная пересборка не создаёт ревизию (ARCH-05: «не изменяет последний согласованный план»), след — в аудите.
3. Согласие при устаревании — через новую корзину, где риск перечислен; API и схемы не менялись.

## Известные ограничения
- Явные выборы пользователя хранятся записями истории (`selection_applied`/`selection_kept`) — без изменения нормативных схем.
- Живой диалог и Live-пересборка не проверены (BLOCKED выше).
