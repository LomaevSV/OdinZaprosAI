# О!дин запрос — AI-турагент из одного сообщения

**Команда Lom · трек «О!дин запрос», хакатон Островок 2026**

Пользователь пишет поездку своими словами — «из Москвы в Казань 20–22 ноября вдвоём, не самолётом,
до 60 000 ₽». Агент понимает условия, задаёт только недостающие вопросы, подбирает транспорт туда и обратно
(ж/д и авиа), гостиницу и трансфер по данным внешних источников, собирает план с итоговой стоимостью
и корзину, имитирует покупку и пересобирает поездку при изменении условий, не теряя уже сказанного.

> **Демонстрационная покупка. Реального бронирования и списания средств нет.**
> Цены, места и расписание из Live-источников действительны на момент запроса и окончательно
> подтверждаются у поставщика. Компоненты с пометкой «ДЕМО» — синтетические: это не цена, не наличие
> и не расписание.

## Демонстрационное видео

- Видео-скринкаст: [Смотреть демонстрацию](https://github.com/ostrovok-hackathon-2026/lom/blob/main/demo/demo.mp4)
- Развёрнутый публичный сервис: не предоставляется; приложение запускается локально (см. ниже).

## Быстрый старт

```bash
git clone <URL репозитория>
cd <каталог репозитория>
docker compose up --build
# открыть http://localhost:8080
```

Ключи и `.env` не нужны: без них используются значения `.env.example` — LLM выключен, данные в режиме
**ДЕМО (Mock)**, сеть не требуется (см. «Запуск без платных API»).

Требования: Docker Compose ≥ 2.24 (используется `env_file` с `required: false`); ориентировочно 1 CPU,
512 MB RAM, ~400 MB диска под образ (оценка, на чистой сборке не измерялась). Сборка — несколько минут.

Включить AI-диалог и Live-данные:

```bash
cp .env.example .env
# в .env:
ODIN_LLM_MODE=live
ODIN_LLM_BASE_URL=https://<провайдер>/v1   # любой OpenAI-совместимый Chat Completions API
ODIN_LLM_MODEL=<модель>
ODIN_LLM_API_KEY=<ключ>
docker compose up --build
```

При настроенной LLM режим данных `auto` переключается на `live`. Включение `ODIN_LLM_MODE=live` означает
согласие на **платные** вызовы выбранного LLM-провайдера.

Локально без Docker (Python 3.12, [uv](https://docs.astral.sh/uv/)):

```bash
uv sync
uv run python -m odin.api     # http://localhost:8080; .env читается автоматически
```

## Как устроен агент

Ключевой принцип: **LLM понимает язык, код отвечает за факты.** Модель используется в двух узких ролях;
даты, цены, наличие, бюджет, выбор предложений, ревизии и корзину рассчитывает и проверяет
детерминированный код.

```
Сообщение ─► Интерпретатор (LLM) ─► проверка цитат, календарь ─► запрос поездки (TripRequest)
                                                                      │
                Политика уточнений ◄──────────────────────────────────┤ не хватает данных → вопросы
                                                                      ▼
                Оркестратор ─► Tool Registry ─► Tutu MCP / Open-Meteo / OSRM (или ДЕМО)
                     │            волна 1: транспорт туда/обратно + гостиницы
                     │            волна 2 (Live): детали лучших гостиниц; трансферы
                     ▼
                Ядро: условия и ранжирование, бюджет, стыки, полнота цены ─► план ─► корзина ─► демо-чек
                     │
                     ▼
                Composer (LLM) ─► ответ пользователю (числа сверяются с таблицей фактов)
```

| Компонент | Что делает | Где |
|---|---|---|
| **Интерпретатор** (LLM) | Извлекает параметры поездки и для каждого возвращает дословную цитату из сообщения. Код принимает значение, только если цитата есть в тексте; даты по фразам («послезавтра», «в середине лета») вычисляет календарь, а не модель. Новые условия накладываются на прежние | `src/odin/llm/free_text.py`, `src/odin/core/calendar.py` |
| **Политика уточнений** | Спрашивает только недостающее одним компактным раундом; варианты дат и городов предлагает кнопками | `src/odin/core/clarify.py` |
| **Оркестратор** | Детерминированный автомат хода: волны поиска, лимиты вызовов и времени, причина остановки поиска, атомарная запись ревизии, аудит | `src/odin/orchestrator.py` |
| **Tool Registry и политика** | Единственный путь к внешним источникам: deny-by-default, список разрешённых «провайдер + инструмент», тайм-ауты, повторы, размыкатель цепи. Оформление заказов у поставщика запрещено | `src/odin/tools/registry.py`, `policy.py` |
| **Адаптеры источников** | Tutu MCP (ж/д, авиа, гостиницы, детали тарифов), Open-Meteo (геокодинг), OSRM (время трансфера); нормализация в единые контракты; ответы поставщиков — данные, а не команды | `src/odin/tools/tutu.py`, `rest_adapters.py`, `untrusted.py` |
| **Ядро** | Условия AND/OR/FALLBACK и ранжирование, подбор под обязательный бюджет, полнота итога, разные валюты не суммируются, проверка стыков «прибытие → заезд» | `src/odin/core/` |
| **Менеджер пересборки** | По таблице зависимостей инвалидирует только затронутые компоненты (например, смена транспорта не сбрасывает выбранную гостиницу) | `src/odin/core/replan.py` |
| **Корзина** | Автомат «черновик → ожидание подтверждения → демо-покупка», два раздельных согласия, идемпотентный демо-чек | `src/odin/core/cart.py` |
| **Composer** (LLM) | Переформулирует ответ по таблице фактов; все числа и даты в тексте сверяются с таблицей, при расхождении используется шаблон | `src/odin/llm/composer.py` |

Без LLM (`ODIN_LLM_MODE=off`) те же условия вводятся структурированной формой и разбираются тем же кодом
(DEC-08); свободный текст в этом режиме честно отклоняется.

**Приватность.** Провайдеру LLM уходит только текущее сообщение и краткие условия поездки, без истории.
Ключи, e-mail, номера телефонов, карт и документов заменяются на `[скрыто]`; тексты пользователей не пишутся
в журналы.

## Сквозной сценарий

1. **Запрос.** «Хочу из Москвы в Казань с 20 по 22 ноября вдвоём, не самолётом, до 60 000 ₽».
2. **Уточнение — только при необходимости.** На «Хочу в Казань» агент одним раундом спросит даты и состав;
   на «в середине лета» предложит конкретные варианты дат кнопками.
3. **Вдохновение.** Без направления («хочу на море из Москвы») — 3 кандидата с ориентировочной стоимостью
   при известных датах; город выбирается нажатием и меняется в любой момент.
4. **Поиск и план.** Колонки «Транспорт туда · Гостиницы · Транспорт обратно» и трансферы; у каждой карточки —
   источник, время актуальности и режим данных. План «поезд → трансфер → отель → трансфер → поезд» с итогом
   и пометкой полноты стоимости.
5. **Выбор.** Нажатием выбирается другой рейс или гостиница — итог пересчитывается, прочие компоненты
   не меняются.
6. **Пересборка.** «А давай самолётом», другие даты, бюджет или состав — план пересобирается, прочие условия
   сохраняются.
7. **Корзина и демо-покупка.** Корзина → подтверждение двумя согласиями (покупка и риски) → демо-чек.
   Реального бронирования нет.

## Контроль предложений, ревизий и корзины

- **Каждое изменение — новая ревизия поездки** в SQLite. Запрос с устаревшим номером ревизии отклоняется
  (HTTP 409) с понятным сообщением в интерфейсе — параллельные действия не перезаписывают друг друга.
- **Выбрать можно только найденное предложение текущей ревизии.** Неизвестный или прежний `offer_id`
  отклоняется.
- **Идентификатор гостиничной котировки** включает гостиницу, даты, состав гостей, номер, тариф, сумму
  и валюту. Изменилась цена — это новая котировка; старая цена не переносится в новый план.
- **Корзина привязана к ревизии.** После пересборки или нового выбора прежняя корзина не подтверждается (409).
- **Подтверждение** требует двух отдельных согласий; повтор с тем же `confirmation_id` возвращает тот же
  демо-чек, а не вторую «покупку».
- **Актуальность.** У предложений есть срок актуальности (по умолчанию 30 минут); устаревшие компоненты
  попадают в список рисков при подтверждении и при пересборке не переносятся как действующие.
- **Наличие честное:** из поисковой выдачи — «не подтверждено»; «есть» — только по деталям предложения
  поставщика на момент запроса.

## Источники данных и режимы

| Источник | Что даёт | Доступ |
|---|---|---|
| Tutu MCP: `search_rail`, `search_avia`, `search_hotels`, `get_offer_details` | ж/д, авиа, гостиницы; детали тарифов лучших гостиниц на даты и состав | публичный MCP, только чтение, ключ не нужен |
| Open-Meteo Geocoding | координаты и часовой пояс городов | публичный API, ключ не нужен |
| OSRM (демо-сервер) | время автотрансфера без пробок | публичный API, ключ не нужен |
| Каталог направлений | кандидаты для «вдохновения» | редакционная заготовка в коде |
| ДЕМО (Mock) | синтетические варианты с пометкой «ДЕМО» | без сети |

`ODIN_DATA_MODE`:

| Режим | Поведение |
|---|---|
| `auto` (по умолчанию) | без ключа LLM — `mock`; при настроенной LLM — `live` |
| `mock` | только ДЕМО-данные, без сети |
| `live` | только внешние источники; при сбое — ранее записанный снимок (Replay) по строгому ключу, иначе честное «неизвестно». ДЕМО не подставляется |
| `mixed` | только по явной настройке: при сбое Live — ДЕМО по компоненту с уведомлением в ответе |
| `replay` | только локальные снимки прошлых Live-ответов, без сети |

Для `live` нужен доступ из контейнера к `mcp.tutu.ru`, `geocoding-api.open-meteo.com`,
`router.project-osrm.org` и к адресу LLM-провайдера.

Чего агент не делает: не оформляет заказы и не регистрирует пассажиров у поставщика, не передаёт ссылки
оформления, не выдумывает цены и наличие при сбое источника.

## Запуск без платных API (режим MOCK)

`docker compose up --build` без `.env` запускает приложение без ключей и без сети:

- данные — синтетические, с пометкой «ДЕМО» на каждой карточке и общим уведомлением о режиме;
- LLM выключен: запрос вводится **структурированной формой** (откуда, куда, даты, гости, бюджет, транспорт,
  пожелания); свободный текст честно отклоняется (DEC-08);
- доступен весь путь: план, выбор вариантов, вдохновение, пересборка, корзина, демо-чек.

Варианты:
- LLM с ДЕМО-данными (без запросов к Tutu и OSRM): ключ LLM + `ODIN_DATA_MODE=mock`;
- локальная модель через OpenAI-совместимый API (например, `http://host.docker.internal:11434/v1`).

Проверка конфигурации без сети и без платных вызовов (ключ не выводится):
`docker compose exec app python -m odin.diagnose`.

## Интерфейс и API

- `/` — интерфейс на русском: единая лента чата, кнопки вариантов дат и городов, панель «Моя поездка»,
  колонки предложений, корзина, демо-чек. При подключённом LLM форма ручного ввода скрыта; для диагностики
  она открывается по адресу `/?manual=1`.
- `/health` — 200 и JSON: режим данных, режим LLM, состояние БД, статус провайдеров.
- `/docs` — OpenAPI. JSON API под `/api/v1`: сессии и сообщения (`/sessions`, `/sessions/{id}/messages`,
  SSE-события `/sessions/{id}/events`), поездки (`/trips/{id}`, `/selections`, `/replan`, `/cart`), корзина
  (`/carts/{id}/confirm`, `/decline`), чеки (`/receipts/{id}`).
- Авторизация и тестовые учётные записи не требуются.

**Сидирование** не нужно: схема SQLite создаётся при первом старте, ДЕМО-данные генерируются
детерминированно. Данные — в томе `odin-data`; сброс: `docker compose down -v`.


Тесты: unit (ядро, календарь, корзина), contract (схемы), adapter (Tutu, Open-Meteo, OSRM на синтетических

## Ограничения

- Наличие мест и номеров из поисковой выдачи не подтверждается; детские ж/д тарифы не запрашиваются.
- Гостиницы Tutu — один номер на 1–6 взрослых и детей до 17 лет; больший состав — явная ошибка источника,
  а не подмена на меньший.
- Время трансфера — оценка OSRM без пробок по ориентировочным координатам вокзалов и аэропортов; стоимость
  трансфера не оценивается, поэтому итог поездки помечается как неполный.
- Стыки «прибытие → заезд» — «неизвестно», пока не утверждены буферы времени.
- Разные валюты не суммируются: итог «неизвестен», цены компонентов сохраняются. Бюджет в форме — в рублях.
- Каталог направлений для вдохновения — редакционная заготовка; климат и визы не проверяются.
- `python -m odin.selfcheck` создаёт демо-сессию, корзину и демо-чек — это не только чтение.

## Структура репозитория

- `src/odin/contracts` — контракты (Pydantic) и экспорт JSON Schema в `schemas/`;
- `src/odin/core` — детерминированное ядро: деньги, календарь, условия, ранжирование, стыки, корзина, пересборка;
- `src/odin/llm` — LLM Gateway, Интерпретатор с проверкой цитат, Composer, минимизация данных;
- `src/odin/tools` — Tool Registry, политика, MCP-клиент, адаптеры Tutu, Open-Meteo, OSRM, Replay, ДЕМО;
- `src/odin/orchestrator.py` — автомат хода; `src/odin/api.py` — API и интерфейс; `src/odin/storage.py` — SQLite;
- `src/odin/static` — интерфейс (HTML, CSS, JS без сборки);
- `config/provider_registry.yaml` — карточки и утверждения провайдеров;
- `docs/` — журнал решений (`decision_log.md`), соответствие заданию (`contest_mapping.md`), отчёты, манифесты.
