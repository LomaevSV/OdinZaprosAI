# О!дин запрос (трек «О!дин запрос», хакатон Островок 2026)

AI-турагент из одного запроса: понимает поездку, описанную своими словами, задаёт только нужные уточнения,
подбирает транспорт (ж/д и авиа), гостиницу и трансфер по реальным данным, сравнивает варианты, собирает план
и корзину, имитирует покупку и пересобирает поездку при изменении условий, не теряя прежних условий.

- Развёрнутый сервис: нет (опционально)

> Демонстрационная покупка. Реального бронирования и списания средств нет.
> Цены, места и расписание из Live-источников — на момент запроса; окончательно они подтверждаются
> у поставщика при оформлении. Компоненты с пометкой «ДЕМО» — синтетические, не цена и не наличие.

## Быстрый старт

```bash
git clone <URL репозитория>
cd <repo>
cp .env.example .env   # необязательно: нужен, только чтобы задать ключ LLM или сменить режим
docker compose up --build
# открыть http://localhost:8080
```

Без `.env` используются значения `.env.example`: LLM выключен, режим данных `auto` → `mock` (резервный ДЕМО-режим без ключей и сети).
Чтобы включить AI-агента, задайте в `.env` ключ OpenAI-совместимого API (см. «LLM» ниже): тогда `auto` переключает данные на `live` (Tutu, Open-Meteo, OSRM) без подмены на ДЕМО. Перезапустите
`docker compose up --build`.

Локально без Docker (Python 3.12 и [uv](https://docs.astral.sh/uv/)):

```bash
uv sync
uv run python -m odin.api     # http://localhost:8080; .env читается автоматически
```

## Зависимости и переменные окружения

Рекомендованные ресурсы: 1 CPU, 512 MB RAM, ~400 MB диска под образ. Сборка — несколько минут.

- Внешних сервисов (БД, кэш) нет: SQLite (WAL) в томе `odin-data` (`/data` в контейнере).
- Сеть во время работы (режим `live`/`mixed`): `mcp.tutu.ru`, `geocoding-api.open-meteo.com`,
  `router.project-osrm.org`; LLM — по адресу из `ODIN_LLM_BASE_URL`. Без сети работает честный ДЕМО-режим.
- Docker Compose ≥ 2.24.

Полный список — `.env.example` (секретов в нём нет; реальные значения — только в `.env`, он исключён из git).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ODIN_DATA_MODE` | `auto` | `auto` — `mock` без ключа LLM, `live` при настроенной LLM; `mock` — только ДЕМО; `live` — без ДЕМО, при сбое «неизвестно»; `mixed` — Live, при сбое ДЕМО по компоненту с уведомлением; `replay` — только снимки |
| `ODIN_LLM_MODE` | `off` | `off` — структурированная форма (DEC-08); `live` — свободный диалог; `replay` — записанные ответы |
| `ODIN_LLM_BASE_URL` | — | Адрес OpenAI-совместимого API, например `https://api.openai.com/v1` |
| `ODIN_LLM_MODEL` | — | Имя модели |
| `ODIN_LLM_API_KEY` | — | Ключ (только в `.env`). Запасные имена: `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL` |
| `ODIN_LLM_COMPOSER` | `true` | Переформулировка ответа моделью с проверкой чисел по таблице фактов |
| `ODIN_LLM_JSON_MODE` / `ODIN_LLM_TEMPERATURE` | `true` / `0` | Совместимость с провайдером (`none` — не передавать) |
| `ODIN_LLM_CALLS_PER_TURN` | `4` | Бюджет вызовов LLM за ход |
| `ODIN_PORT` | `8080` | Порт приложения в контейнере (Compose пробрасывает `8080:8080`) |
| `ODIN_DB_PATH` | `/data/odin.sqlite3` | SQLite (в Docker); локально `var/odin.sqlite3` |
| `ODIN_REPLAY_DIR` | `/data/replay_store` | Локальные снимки Live-ответов для Replay (вне git) |
| `ODIN_TURN_DEADLINE_S` / `ODIN_TOOL_TIMEOUT_S` | `60` / `20` | Дедлайн хода и вызова инструмента |
| `ODIN_OFFER_TTL_MINUTES` | `30` | Срок актуальности предложений (provisional, DEC-21) |

### LLM
Любой OpenAI-совместимый Chat Completions API (облачный или локальный, например `http://host.docker.internal:11434/v1`).
Пример `.env`:
```bash
ODIN_LLM_MODE=live
ODIN_LLM_BASE_URL=https://<провайдер>/v1
ODIN_LLM_MODEL=<модель>
ODIN_LLM_API_KEY=<ключ>
```
Включение `live` — это разрешение оператора на платные вызовы. Модель только извлекает параметры с дословными
цитатами из сообщения и переформулирует ответ; даты, цены, условия и наличие проверяет код.

- Вызовов за ход: обычно 2 (Интерпретатор + Composer), не больше `ODIN_LLM_CALLS_PER_TURN` (4: повтор по формату
  и повтор транспорта). `ODIN_LLM_COMPOSER=false` — 1 вызов за ход, ответ по шаблону.
- Модель: подойдёт любая быстрая модель с JSON-ответами (ход ограничен `ODIN_LLM_TIMEOUT_S=20`). Для «рассуждающих»
  моделей, не принимающих `temperature`/`max_tokens`, клиент делает совместимый повтор — это лишний запрос.
- При настроенной LLM `auto` включает Live-данные. LLM с ДЕМО-данными (без сети Tutu/OSRM): `ODIN_DATA_MODE=mock`.
- Проверка конфигурации без сети и без платных вызовов (ключ не выводится):
  `uv run python -m odin.diagnose` (в Docker: `docker compose exec app python -m odin.diagnose`).

**Приватность.** Тексты передаются провайдеру только при `ODIN_LLM_MODE=live`: текущее сообщение и краткие
условия поездки, без истории переписки. Ключи, e-mail, номера телефонов, карт и документов заменяются на
`[скрыто]` до отправки, пользователь видит уведомление в интерфейсе (`privacy_notice` в ответе
`POST /api/v1/sessions`) и в ответе, если что-то было скрыто. Тексты не пишутся в журналы; в журнал вызовов
LLM попадают только роль, статус, задержка и число токенов. Форма отправляется без LLM.

## Сидирование

Ничего выполнять не нужно: схема SQLite создаётся при первом старте контейнера, демо-данные генерируются
детерминированно. Сброс данных: `docker compose down -v`.

## Маршруты/доступ

- `/` — UI (чат, форма, «Моя поездка», карточки вариантов с режимом и источником, корзина, демо-чек)
- `/health` — 200 OK, JSON `{"status": "ok", "data_mode": ..., "llm_mode": ..., "providers": [...]}`
- `/docs` — OpenAPI; JSON API под `/api/v1` (сессии, сообщения, поездки, выбор, пересборка, корзина, подтверждение)
- Тестовых учётных записей нет — авторизация не требуется.

## Демонстрационный сценарий
1. «Хочу из Москвы в Казань с 20 по 22 ноября вдвоём, не самолётом, до 60 000 ₽» (LLM) — или та же форма:
   план «поезд → трансфер → отель → трансфер → поезд», итог с пометкой полноты.
2. «Хочу в Казань» — один компактный раунд уточнений; ответ дополняет полученное, повторных вопросов нет.
3. «А давай самолётом» / изменить даты, бюджет, состав — пересборка сохраняет прочие условия;
   старая корзина больше не подтверждается (409).
4. Корзина → два раздельных согласия (покупка и риски) → демо-чек; повтор подтверждения возвращает тот же чек.
5. Без направления, с пожеланиями («к морю») — кандидаты направлений с оценкой стоимости при известных датах.

## Режимы данных и провайдеры
| Источник | Что даёт | Статус |
|---|---|---|
| Tutu MCP (`search_rail`, `search_avia`, `search_hotels`, `get_offer_details`) | ж/д, авиа, гостиницы; детали лучших гостиниц (тарифы и наличие на даты); только чтение | утверждён (DEC-09) |
| Open-Meteo geocoding | координаты и часовой пояс городов | утверждён (DEC-09) |
| OSRM (демо-сервер) | оценка времени трансфера на авто без пробок | утверждён (DEC-09) |
| Mock «ДЕМО» | синтетические варианты с пометкой | `mock` и запасной путь `mixed` |
| Replay | снимки прошлых Live-ответов, строгий ключ | `ODIN_REPLAY_DIR`; снимки пишутся при успешных Live-запросах, в репозитории их нет (DEC-24) |

Запрещено всегда: оформление заказов и регистрация пассажиров (`register_checkout_passengers`), ссылки
оформления (DEC-10). Наличие из поисковой выдачи — «не подтверждено» (`unknown`); «есть» — только по деталям
предложения от поставщика и только на момент запроса. Сборы при оформлении не подтверждены — итог `partial`.

## Диагностика
| Симптом | Причина и действие |
|---|---|
| «Свободный диалог недоступен» | LLM выключен (`ODIN_LLM_MODE=off`) или ошибка провайдера (код в ответе: `auth_401`, `rate_limited`, `timeout`). Проверка: `python -m odin.diagnose`; форма работает без LLM |
| Приложение не стартует с `ConfigError` | `ODIN_LLM_MODE=live` без ключа/адреса/модели или `http://` для нелокального хоста — текст ошибки называет переменную |
| Компоненты с пометкой «ДЕМО» | режим `mock` (нет ключа LLM) или явный `mixed` после сбоя Live; в `live` ДЕМО не подставляется |
| План пустой, «источник недоступен» | нет сети до `mcp.tutu.ru` / Open-Meteo / OSRM; для показа без сети — `ODIN_DATA_MODE=mock` (`replay` — только если ранее записаны снимки в `ODIN_REPLAY_DIR`) |
| Порт 8080 занят | `ODIN_PORT=8090` (локально) или другой порт слева в `ports` Compose; на Windows часть портов резервирует система (`winerror 10013`) — выберите другой |
| `docker compose` ругается на `env_file` | нужен Docker Compose ≥ 2.24 (`docker compose version`) |
| `/health` | режим данных, режим LLM и провайдеры; ход и вызовы — в журнале контейнера (без текстов пользователя) |

## Структура
- `src/odin/contracts` — единый набор контрактов, экспорт JSON Schema в `schemas/`;
- `src/odin/core` — детерминированное ядро: деньги, календарь, условия, ранжирование, стыки, корзина, пересборка;
- `src/odin/llm` — LLM Gateway (OpenAI-совместимый клиент), Интерпретатор с проверкой цитат, Composer;
- `src/odin/tools` — Tool Registry, политика deny-by-default, MCP-клиент, адаптеры Tutu/Open-Meteo/OSRM, Replay, Mock;
- `src/odin/orchestrator.py` — автомат хода; `src/odin/api.py` — JSON API и UI; `src/odin/storage.py` — SQLite;
- `config/provider_registry.yaml` — карточки и утверждения провайдеров; `docs/` — решения, план, отчёты.

## Ограничения
- Без ключа LLM свободный текст честно отклоняется, работает структурированная форма (DEC-08).
- Наличие мест и номеров из поисковой выдачи не подтверждается (`unknown`); детские ж/д тарифы не запрашиваются.
- Время трансфера — оценка OSRM без пробок по ориентировочным координатам вокзалов/аэропортов; стоимость не
  оценивается (DEC-18); стыки «прибытие → заезд» — `unknown`, пока буферы не утверждены (DEC-20).
- Разные валюты не суммируются (DEC-17); поиск нескольких номеров в Tutu недоступен.
- Каталог вдохновения — редакционная заготовка (DEC-28); визы не проверяются.

## Лицензии и происхождение данных
Происхождение данных — `docs/data_manifest.yaml`. Сторонние ответы провайдеров в репозиторий не включены:
тестовые фикстуры синтетические (DEC-11, DEC-33). Open-Meteo — CC BY 4.0, OSRM — данные OpenStreetMap (ODbL).
Зависимости — из `uv.lock` под их собственными лицензиями. Юридическая проверка поставки — **BLOCKED** до DEC-33.
