# О!дин запрос

Прототип AI-турагента (трек «О!дин запрос»): запрос → уточнение → варианты → сравнение → план →
корзина → явное подтверждение → демо-чек; пересборка после изменения условий.

> **Статус: срез S6, только ДЕМО-данные (Mock).** Цены, наличие и расписание не настоящие.
> Демонстрационная покупка. Реального бронирования и списания средств нет.
> Свободный диалог требует LLM (DEC-07) и сейчас недоступен — используется структурированная форма (DEC-08).
> Live-провайдеры не подключены до решений руководителя (DEC-04, DEC-09, DEC-11).

## Быстрый старт (локально)
Требуется Python 3.12 и [uv](https://docs.astral.sh/uv/). Платные ключи не нужны.

```sh
uv sync                       # зависимости из uv.lock в .venv
cp .env.example .env          # ODIN_DATA_MODE=mock, ODIN_LLM_MODE=off
uv run python -m odin.api     # http://127.0.0.1:8080
```

Откройте `http://127.0.0.1:8080/` — интерфейс, `http://127.0.0.1:8080/docs` — JSON API, `/health` — состояние.
База SQLite (WAL) и её схема создаются автоматически при первом запуске (`ODIN_DB_PATH`); отдельных миграций нет.

## Демонстрационный сценарий (Mock)
1. Форма: Москва → Казань, даты, 2 взрослых, туда и обратно → план (поезд, отель, трансфер), итог `partial`.
2. Без числа взрослых система задаёт один вопрос; ответ дополняет форму, повторных вопросов нет.
3. Измените даты, бюджет, добавьте собаку или взрослого — пересборка сохраняет прочие условия;
   старая корзина больше не подтверждается (409).
4. Корзина → два раздельных согласия (покупка и риски) → демо-чек; повтор подтверждения возвращает тот же чек.
5. Без направления, с пожеланиями — кандидаты; при известных датах — ДЕМО-оценка стоимости и времени пути.

## Режимы данных и провайдеры
| Режим | Статус |
|---|---|
| `mock` | работает; синтетические данные с пометкой «ДЕМО», доступность всегда `unknown` |
| `replay` | маршрутизатор и строгий ключ готовы; снимков нет (DEC-24) |
| `live` | **BLOCKED**: провайдеры в `config/provider_registry.yaml` имеют `approval_status=proposed` (DEC-09) |

## Переменные окружения
Полный список — `.env.example`. Секреты хранятся только в `.env` (исключён из git).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ODIN_DATA_MODE` | `mock` | Разрешён только `mock` (DEC-23) |
| `ODIN_LLM_MODE` | `off` | `off` / `replay`; `live` — после DEC-07 |
| `ODIN_DB_PATH` | `var/odin.sqlite3` | SQLite (WAL) |
| `ODIN_PORT` | `8080` | Порт HTTP |
| `ODIN_OFFER_TTL_MINUTES` | `30` | Provisional TTL офферов (DEC-21) |

## Структура
- `src/odin/contracts` — единый набор контрактов (ТЗ §7), экспорт JSON Schema в `schemas/`;
- `src/odin/core` — детерминированное ядро: деньги, условия, ранжирование, стыки, корзина, уточнения, пересборка;
- `src/odin/tools` — Tool Registry, политика deny-by-default, Mock-адаптеры;
- `src/odin/llm` — LLM Gateway (`off`/`replay`), интерпретатор формы, Composer по таблице фактов;
- `src/odin/orchestrator.py` — автомат хода; `src/odin/storage.py` — SQLite; `src/odin/api.py` — JSON API;
- `src/odin/static` — интерфейс без сборки;
- `tests/corpus` — корпус K-01..K-30 и прогонщик;
- `docs/` — план, журнал решений, манифесты (`data_manifest.yaml`, `release_manifest.yaml`), отчёты.

## Ограничения
- Live-провайдеры, геокодинг, климатические нормы и 2ГИС не подключены (DEC-09, DEC-12, DEC-13).
- Доступность Mock всегда `unknown`; стоимость трансфера не оценивается (DEC-18) — итог `partial`.
- Стыки «прибытие → заезд» — `unknown`, пока буферы не утверждены (DEC-20).
- Допущения о составе группы не делаются (DEC-25); TTL офферов 30 мин — provisional (DEC-21).
- Каталог вдохновения — демо-заготовка из 5 направлений (DEC-28 открыт).

## Лицензии и происхождение данных
Происхождение и права на все включённые данные — `docs/data_manifest.yaml`. Сторонние данные в репозиторий
не включены (DEC-33). Зависимости — из `uv.lock` под их собственными лицензиями.
Юридическая проверка поставки (LEGAL-01, п. 7.3 условий конкурса) — **BLOCKED** до DEC-33.
